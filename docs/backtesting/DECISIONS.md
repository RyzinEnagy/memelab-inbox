- D-BT-006 (2026-10-23, Phase 00): Phase 00 changes no lab code. - D-BT-007 (2026-10-23, Phase 00): the lab's exported history (`data/state/latest.json` on `main`, 89 commits) is the primary point-in-time discovery universe. `created_at` is the lab's own observation time; the git commit time is an independent upper bound on when a record existed.
- D-BT-008 (2026-10-23, Phase 01): architecture accepted as in audits/backtesting/ARCHITECTURE_DECISION.md: new package `memelab/backtest/`, hook after `analyze_token` in the scout/analyze CLI behind an off-by-default policy, additive bt_* tables with append-only triggers, evidence tiers TOKEN_SPECIFIC / HISTORICAL_COHORT / SCENARIO_ONLY / UNAVAILABLE, execution fidelity ladder EXACT_CPMM / QUOTE_OBSERVED / LIQ_SNAPSHOT_APPROX / UNSUPPORTED_POOL.
- D-BT-009 (2026-10-23, Phase 01): research rubric R1.0 locked with the base weights unchanged (research/RUBRIC_LOCK.md).
- D-BT-010 (2026-10-23, Phase 01): the discovery universe is the union of theses and rejections across all git versions of data/state/latest.json, not the latest file (1,801 vs 701 theses).
- D-BT-011 (2026-10-23, Phase 01): exact historical execution is BLOCKED (no reserves/ticks/bins source); historical fills use LIQ_SNAPSHOT_APPROX or QUOTE_OBSERVED with labels.
- D-BT-012 (2026-10-23, Phase 03): no reviewed repository reaches the 70-point adoption threshold (best: slotfish 65.10 primary, 59.30 blind). Build a purpose-built engine in `memelab/backtest`, informed by ideas from slotfish, basana, sol-trade and backtesting.py, with independent test oracles. No copyleft or unlicensed code copied. To be confirmed by the Phase 04 bake-off.
- D-BT-013 (2026-10-23, Phase 03): engine fill conventions fixed from review findings: next bar open after decision plus latency (never the signal bar), gap-through stops fill at the open, stop-loss wins when stop and take-profit are both inside one bar, PumpSwap priced on effective quote reserves (vault + signed virtual_quote_reserves).
- D-BT-014 (2026-10-23, Phase 04): bake-off confirms D-BT-012. Engine, CPMM math, validation and analytics are reimplemented (no new runtime dependency). backtesting.py and vectorbt are audit-only external oracles in isolated venvs. CLMM/DLMM historical fills are not implemented (UNSUPPORTED_POOL unless a quote observed at decision time exists).
- D-BT-015 (2026-10-23, Phase 04): Maxun: AGPL source integration NO-GO without Elving's legal decision; self-hosting not authorized; a thin Maxun Cloud API client is license-compatible and is evaluated in Phase 06A.
- D-BT-016 (2026-10-23, Phase 05): `tools/release_audit.py` gains five narrow reviewed-hit entries (backtesting audit notes, prompt package, isolated smoke scripts, one env-var-name match in a smoke output, backtest refusal-list tests). Code under `memelab/backtest/` gets no exemption.
- D-BT-017 (2026-10-23, Phase 05): bt schema is created lazily by the backtest package, not by `db.init_db`. Backfilled market bars are available at end + provider lag (modeled, flagged); later revisions only from their own observation time.
- D-BT-018 (2026-10-23, Phase 06): backtest data lives in its own SQLite file `data/backtest/bt.sqlite` (env `MEMELAB_BT_DB`), gitignored, with raw provider responses under `data/backtest/raw/`. The lab's tracked database is never written by the backtest package. A small real fixture is committed under `tests/fixtures/backtest/real/`.
- D-BT-019 (2026-10-23, Phase 06): corpus resume counts a mint as done only after its bar fetches complete (`CORPUS_MINT_DONE` marker), not when its pool list was fetched. Corrupted mint strings in the lab's exports are reported (GAPS C4) and never merged by similarity.
- D-BT-020 (2026-10-23, Phase 06A): Maxun NOT_ADOPTED (EXISTING_TOOL_WINS for the catalyst watch; release watch uses the GitHub Releases API). Public pages enter the lab only through `memelab/backtest/sources/webcapture.py` with use-case allowlists, page caps and a claim fingerprint; Maxun is refused as a runtime collector. The evaluation robot stays idle with no schedule.
- D-BT-021 (2026-10-23, Phase 07): PumpSwap fees are per pool (observed 0.30%, 0.55%, 1.25%); historical runs use 1.25% unless the pool's fee was observed, labeled ASSUMED_UPPER_OBSERVED_TIER. PumpSwap pricing uses effective quote reserves (vault plus the signed virtual quote reserve at byte 245 of the pool account), confirmed against live Jupiter quotes within 0.02%.
- D-BT-022 (2026-10-23, Phase 09): historical catalysts come from the lab's own contemporaneous records (launch monitor in the committed state exports, first value kept; catalyst tables when present). Claimed event times are never decision times. Wallet observations count as selling only when they are verified swap sales with an availability time; transfers, custody moves and inferences never do.
- D-BT-023 (2026-10-23, Phase 10): the research runner lives in the existing CLI as `python -m memelab backtest` (status, run). A bar that crashes more than 50% through a stop and closes below it is exited at its close, not at the stop. Run ids include a content hash of the backtest package. The discovery baseline makes one attempt only.
- D-BT-024 (2026-10-23, Phase 11): no interval or p-value from fewer than 5 days of exits, and no strategy enters a multiple-comparison test below 30 sealed-test trades. Current verdict for every strategy: INSUFFICIENT_SAMPLE. The only interval that excludes zero (walk-forward BREAKOUT_CLOSE) is negative.
- D-BT-025 (2026-10-23, Phase 13): the scout and analyze commands call `memelab/backtest/hook.py` after `analyze_token`. It is off by default (`data/backtest/policy.json` or `MEMELAB_BACKTEST=1`); when off it returns before touching any database and output is byte-identical. When on, the assessment is a separate record (`r["backtest_assessment"]`, `bt_assessments`); it never edits the lab's score, status, fatal flags or report. Severe stress becomes the flag BT_STRUCTURALLY_UNTRADEABLE beside the score, not a score change.
- D-BT-026 (2026-10-23, Phase 13): request key = sha256(chain, mint, snapshot hash, engine version, policy hash, data revision), where the data revision is the highest row id of the append-only bar and universe tables. A cached answer asked for after the snapshot is 2 h old returns STALE_DATA. Catalyst refreshes require a verified mint, the same mint, availability after the last assessment, a new origin and content, and a source status of OK; a refresh only asks for re-analysis and never creates a verdict.
- D-BT-027 (2026-10-23, Phase 14): reports use schema `memelab.backtest.report/1` (docs/backtesting/REPORTS.md, REPORT_SCHEMA.json). Labels in order: FATAL FLAW, UNTESTED, BAD EXECUTION, INCONCLUSIVE, TESTED; a missing assessment is UNTESTED. Strategies are ranked by net return after modeled costs, never by paper, and only with at least 30 trades. The scout section, per-mint report files and the alert `Backtest:` line exist only when the backtesting policy is on; alert dedupe, cooldowns and caps are unchanged. New CLI modes live under the existing `python -m memelab backtest` command (stress, assess, inspect, data, schema, run --as-of).
- D-BT-028 (2026-10-23, Phase 14): the assessment request key also hashes the token's own hourly bar history (amends D-BT-026); a cache hit with different bars had returned the wrong assessment. Catalyst-triggered refreshes are limited to one per mint per hour.
- D-BT-029 (2026-10-23, Phase 15): outcomes protocol outcomes-v1 (windows 1, 6, 24, 72 h; entry reference is the first open after the decision on the pool chosen as in the runner). Opportunities are the lab's frozen records (first appearance per mint and status, all screened-out rejections, stored assessments). Missing outcomes are CENSORED or NOT_OBSERVABLE with a reason, never dropped; outcome rows are append-only with supersede links. Segments use only information available at the decision. Deviations open a REEVALUATION_PROPOSED record that requires a new pre-registration, a new sealed split and a new strategy version; in-place retuning is refused. Maxun is not monitored because it was not adopted.
- D-BT-030 (2026-10-23, Phase 16): release classification is scenario-only research mode, clearly labeled; not an empirically validated engine. G16 (multi-hop routes not modeled) and G27 (sealed window seen by Phase 10 runs before pre-registration; a new sealed test needs data after 2026-10-23 16:00 UTC) are recorded as disclosed limitations by the builder, pending Elving's acceptance; rejecting either makes Phase 16 FAILED.
- D-BT-031 (2026-10-23, Phase 16): cohort evidence and outcomes share one measurement path (outcomes.outcome_for): point-in-time as-of, one pool per token chosen no later than the as-of, windows where the other pools disagree by more than 30% in at least 2 and a third of shared hours are refused (fail closed rather than pick a pool by volume), windows whose feed stopped count at their last traded price, and selection bias is flagged. Engine bt-0.2.0 (partial-exit accounting, network fee in the cash check); fully sold trade records keep the bt-0.1.0 shape.
