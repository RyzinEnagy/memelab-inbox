## 2. Operational verdict and decision gate

The system has real, substantial independently tested *component* behavior: normalized ingest can store evidence, model-free feed rendering can refuse bad data, alert policy can cap and deduplicate candidate events, migrations can coexist with legacy data, and private wording/model responses have a retention table. Those are meaningful strengths. They do not establish a *service*. The runbook says daily/weekly schedules are disabled templates, and the existing scheduled discovery/watchlist jobs do not invoke social collection. Core X/Telegram ingestion cannot automatically carry private text into token identification and claims (AUD-003); there is no automatic end-to-end signal recording (AUD-007). An individual's social source feed therefore cannot currently meet the stated purpose unattended.

**Release decision:** REJECT unattended activation. Permit only an explicitly supervised offline/paper-research pilot with clear `INCOMPLETE / STALE / UNVERIFIED` labels. Fix automatic orchestration and completeness detection before paying for large-scale source access. Do not grant permission to send notifications or activate paid providers merely because the existing fixture suite passes.

**Failure-budget recommendation:** make each scheduled run persist `expected_start`, `start`, `complete`, `source_watermarks`, `attempted_sources`, `success_sources`, `gaps`, `raw/eligible/classified post counts`, `published_at`, `previous_good_run`, `cost_actual` and `cost_reserved`. If the job is absent at its deadline, an independent watchdog must report a missed execution; application heartbeats alone do not detect a scheduler that never started. The default should be **degraded/unknown**, not a reassuring empty digest.

## 5. Cost model as of 2026-10-13

**Published price anchors:** X Developer Platform currently lists **$0.005 per Post: Read resource** (usage-based; changed from older fixed-plan expectations), with additional possible user-lookup resource charges (`https://developer.x.com/`). Anthropic's current **Claude Haiku 5.5** is **$0.10 / million input** and **$0.50 / million output tokens** for prompts up to 100k (`https://www.anthropic.com/claude/haiku`; `https://platform.claude.com/docs/en/about-claude/pricing`). Helius lists **1M credits/month free**, **Developer $49/month for 10M credits**, with per-method credit weights; some requests count more than one (`https://www.helius.dev/pricing`). DEX Screener documents public pair endpoints, including up to **30 tokens per request**, and endpoint limits **60/300 requests per minute** (`https://docs.dexscreener.com/api/reference`). Provider pricing, quota implementation and policy may change; confirm **at the deployment account**, not from this report alone.

**Explicit hypothetical assumptions (not measured production usage):** 30 days/month; 50% of monitored posts are **charged X reads** (and charged once, with no repeated reads); 30% of monitored posts receive a model call after cheap deterministic filters; each model call consumes **1,800 input + 250 output tokens** at Haiku 5.5 short-prompt price. Helius work is arbitrarily estimated at **30k / 300k / 3M credits per month** for the three scenarios (not forecast from code). Free compute on an existing personal machine; a VPS, backups, email provider, higher-cost on-chain/candle data, user-resource reads, over-fetch, failed billed calls, taxes and monitoring software are **excluded**. X terms, availability and resource reuse may alter this substantially.

|---|---:|---:|---:|---:|---:|---:|---|---:|

These are **illustrations, not quotes, bills or automatic cap settings**. A full-X exposure (100% instead of 50%) adds an additional **$7.50 / $75 / $750** monthly respectively, before repeat reads and user lookups. If using a more expensive model, longer posts/system prompts, more than one inference per post, repeated retries or transcription, multiply the relevant units accordingly. The system currently does **not** guarantee that its source costs are bounded by these modeled values.

**FinOps implications:** at medium volume an effective 10× surge changes illustrated spend from ~$78 to ~$826 per month. X alone is ~96% of the X+Haiku line items; optimizing the model by 50% saves ~$1.37/month at medium, while avoiding 10,000 unnecessary X reads saves **$50**. The correct lever is scoped source collection and charged-resource avoidance. Record planned versus actual read resources, cache hit rates, prompt tokens, model version and rate, reservations and invoices; enforce **per-provider hard paid-unit ceilings** with atomic reservations, not only predicted dollar amounts. Confirm X's current rules before implementing any reuse/caching.

### Storage growth model

Assume **3 KB of persistent indexed metadata/derived records per retained post** (illustrative; real schema has multiple rows and may use substantially more), with 365-day retention. This produces approximately **0.11 / 1.10 / 10.95 GB per year** at 100 / 1,000 / 10,000 posts/day before journals, indexes outside the assumption, revisions, model-response caches and backups. Keeping 30 days of 1 KB private text per post adds about 3 / 30 / 300 MB of active private text in those scenarios; retention only helps if purge is scheduled and secure deletion limitations are understood. Two full backup copies can approximately triple disk allocated to DB files. **Do not treat these rough multipliers as measured capacity planning.** Collect actual `page_count`, `page_size`, WAL size, rows and oldest/newest timestamps per table before choosing a retention policy.

### Economical alternatives / simplifications

1. Start with **20–50 verified human sources**, a finite watchlist, and high-value event types; prioritize source independence and credibility over total post volume.
2. Prefer free/low-cost **DEX Screener batched token pairs** and Helius free credits for narrow corroboration before buying premium streams. Market API snapshots are *not* executable trade-depth quotes.
3. Keep the deterministic contract parser and source hash dedup; invoke the inexpensive model only for ambiguous, novel, high-value claims. Cache by `source_id + content_hash + prompt_version + model_id + classification_policy`, with rights-compliant retention.
4. Schedule one 24-hour source summary and **only exceptional risk alerts** initially. Avoid duplicate feeds, per-post expensive classifications, redundant own-state JSON pipelines and multiple platforms with no incremental information.
5. Retain local SQLite with an **encrypted, tested multi-store backup** and a single external scheduler/watchdog on the persistent host. Do **not** move to Kubernetes, distributed queues or Postgres without measured need.
6. Treat extra Reddit/Farcaster/Discord/YouTube integrations as **optional** branch work until core X/TG source-to-claim reliability is fixed and platform permissions/costs justified.

## 6. Diagnostic and usability review: seven user questions

| Nontechnical question | What the current components help answer | Missing for an independent investor |
|---|---|---|
| **What happened?** | Narrative and feed provide token, theme, recency and changed source stance when input exists. | A one-screen event timeline showing *new since last brief*, confidence in coverage and how the conclusion changed. |
| **Who said it?** | Source/witness metadata, distinct originators and citations. | Verified account link, independent source count, grouped amplification/reposts and human-readable context without raw private text exposure. |
| **How credible?** | Registry/identity and evidence vocabulary; wallet self-claim is not ownership proof. | Calibrated performance score based on real forward outcomes, sample size, missing observations and an explicit **NOT RANKABLE** state. |
| **What changed?** | Prior stance comparison and narrative snapshots. | Freeze same-time knowledge state; explain what was newly *learned* versus newly *occurred*. Current historical selection has established look-ahead defects. |
| **What evidence supports it?** | Claim provenance, cluster members and report citations. | All published conclusions need an immutable dependency manifest, evidence availability timestamps and an on-click proof trail. |
| **What should I investigate?** | Brief flags, potential catalyst/risk context and optional scout enrichment. | A ranked checklist of **next research actions**, not auto-trade recommendations, with exact token contract, unsupported claims and source links. |
| **What are the risks?** | Transfer/ownership/on-chain flags in related research components; alert `risk` policy. | Uncertain or missing liquidity/exit quotes must be **UNKNOWN**, not “safe”; separate factual selling/transfer from interpretation; explicit stale/provider gap warnings. |

**A useful default research digest** would begin: `Sources expected / reached / failed; posts fetched / deduplicated / classified; last successful complete collection; paid spend / cap; last complete analysis time; largest gap; alert delivery state`. Only then show at most five meaningful new insights, ordered by credibility and investigation priority, each with chain+contract, what changed, independent sources, observations vs inferences, links, liquidity caveat, and one **what would disconfirm this** sentence. A no-signal day must say “**No qualifying signals in [N processed posts from M/K expected sources]; [K−M] sources unobserved**,” not a bare “Nothing happened.”

A first-run experience should provide a self-test and a truthful state: **DEMO ONLY**, **LIVE DATA DISABLED**, **COLLECTING**, **PARTIAL**, **STALE**, **OPERATIONAL**. `OPERATIONAL` requires recent real successful collection, chain/contract linked claims, budget health, alert heartbeat and a verified restore—not merely valid configuration or pretty fixture output. Evaluate usability with at least five layperson readers using blinded reports and tasks measuring accurate answers, false confidence and minutes to identify a risk; no such study was found.

## 8. Minimum future acceptance gates (not run in Phase 05)

- **Seven-day soak:** run a clock-advanced seven-day replay with 2h polling, one 24h complete outage, one intermittent 429, and a restart; no permanently skipped IDs or duplicate published insights; every gap, stale status, recovery and missed job is recorded.
- **RPO/RTO:** for a personal-scale product **propose** recovery point ≤24h and restore time ≤2h; measure and agree to targets before release. Ensure private material never appears in public Git history.
- **Operating cash:** pre-authorize a **user-selected** provider budget; a 10× input surge and two concurrent workers may not bill past it. Preserve operator override only with deliberate new consent.
- **No-data semantics:** 0 sources reached ≠ 0 matching stories; all seven UX questions answerable or explicitly `UNKNOWN` with supporting coverage/evidence links.
- **ROI:** measure 14 days of manual baseline research and 14 comparable days assisted; outcome metrics include time-to-find, correct signal identification, false positives, misses, time spent repairing the system and incremental paid provider spend. No savings assertion without this trial.
