## Findings

No MATERIAL finding. Nothing changes a number, the primary verdicts, the champion or the status logic.

- m1 (MINOR, wording that can be read as skill). Two committed files carry `SKILL_INDICATED_RETROSPECTIVE_HOLDOUT` for T1 P07_B1 against B0 (BSS +0.016, Holm 0.032, max-T 0.991): the `verdict` column of `HOLDOUT_METRICS.csv` (disclosed, with `skill_after_selection_correction` = 0 beside it) and the `verdict` column of `FULL_EXPERIMENT_LEDGER.csv` row `P12:...:P07_B1_vs_B0`, which has no correction column at all. The ledger is the one ROADMAP names as the cumulative ledger later phases add to, and the disclosures (evidence item 2, the RESULTS limitation) name only the metrics file. PI-D-065 item 3 does say the B1 pattern is descriptive only. Fix in the repair pass (records only, outputs stay as written): name the ledger row in PI-D-065 and HANDOFF as Holm-only, not a claim, and have the next ledger writer carry `skill_after_selection_correction` beside any SKILL verdict.
- m2 (MINOR, tests that cannot fail on the correction details). Five of my 12 mutations of `evaluation.py` survive the 42 unit tests: four in `max_t` (strict exceedance, undefined replicates, family limited to one target, missing +1) and one in `champion` (any non-INSUFFICIENT verdict accepted). On this holdout none changes a result: the code's output equals my independent max-T (row 9), a T1-only family still gives B1 p 0.888 (exploratory), and the development files hold only INSUFFICIENT verdicts. They matter if Phase 19 reuses `max_t` and `champion`. Add a test with a hand-computed max-T p on a tiny fixture (pins `>=`, +1, the cross-target family and the undefined-replicate rule) and a champion test with NOT_DISTINGUISHABLE and WORSE rows.
- m3 (MINOR, N_search scope). The 118 leaves out three non-probability rules scored on real development data and stored as `other`: B4C (DESCRIPTION_ONLY), R0_OC_VETO and R3_SC_AMPLIFICATION_ALARM, 9 (target, rule) pairs. Counting them gives 127; B1's Bonferroni would be 0.032, still below 0.05, so the frozen rule's outcome is the same (it fails max-T anyway). The protocol defines N_search as candidate configurations, so this is a scope note, not a defect. The bake-off count is generous (environment duplicates and a summary row counted), which offsets it.
- m4 (MINOR, procedural seal). The sealed label file is a tracked, public file; any script can read it without a log entry (this review's own recompute did, and nothing recorded it except this file). The single-opening guarantee rests on commit order and honesty, and the debug run 3 "scratch wrapper" (two attempts cut by a timeout) is not kept. The evidence available is consistent with no early look: plan, code and predictions were committed before the logged opening, the champion rule had no input that a peek could change, and the pre-registered choices made in Phase 12 (20,000 replicates, centred max-T, B2 by default) are neutral or conservative. Not fixable for the retrospective holdout; for Phase 19 keep the prospective labels out of the repository until the plan and predictions are committed.
- m5 (MINOR, undisclosed structural limit; see CX-S12). Every secondary row against B2 (51 with numbers) has `p_max_t` empty, and the runner requires `p_max_t < 0.05` for `skill_after_selection_correction`, so a card could never be shown to beat B2 after correction, whatever the data. The protocol defines max-T against B0 only, so the code follows the plan, but checklist G13 lists "a missing correction" as a fail condition and `FINAL_HOLDOUT_RESULTS.md` says "on T1b, nine cards ... none survives the correction" without saying they could not. On this holdout no vs-B2 row passes Holm either (smallest Holm p 0.147), so no verdict changes. Disclose it in the results and PI-D-065; Phase 16 and 19 plans must define the correction for the champion_over_B2 comparison before their data are read.

## Counterexample CX-S12 (new)

Wrong but plausible: a reader of Phase 12 (or Phase 19 reusing the runner's correction rule) takes "0 of 129 secondary comparisons survive the selection correction" to include "no frozen card beats B2 after correction", which is the comparison that matters for `champion_over_B2`. In fact the rule cannot report any vs-B2 row as surviving. `p12_cx_s12.py` (synthetic data only, no holdout label) builds three 70-row, 7-day targets where a candidate X is far better than both references, applies the phase's own `E.holm`, `E.max_t`, `E.bonferroni(p, 118)` and the runner's exact rule (`run_holdout.py` lines 725 to 728). Output: X against B0 survives on every target (p 0.00005, Holm 0.0003, Bonferroni 0.006, max-T 0.00005); X against B2 has the same raw, Holm and Bonferroni values, a max-T against B2 would give 0.00005, yet `skill_after_selection_correction` is False because `p_max_t` is None. Nothing catches this: no unit test covers the runner's `corrected` expression, the outputs test only checks that every row is 0, and the results text does not mention it. It does not change any Phase 12 conclusion (row 9 and m5).
