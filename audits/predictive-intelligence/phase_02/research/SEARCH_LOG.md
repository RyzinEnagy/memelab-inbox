## Verification of each lead

For every lead taken forward (175 inputs: first 141, namely the 36 seeds as written, 86 leads from the corpus and PyPI cross-links, 4 of them added to trace renamed or vanished seeds, and 19 screening tests for README-only claims, forks, mirrors, renames and crawler tooling; then 34 in repair pass 2: the six need-matching names the skeptic found, the two new query families and three successor paths):

1. `git ls-remote https://github.com/<owner>/<name> HEAD` gives the pin and the UTC time it was observed. A failure is VANISHED_OR_PRIVATE, never replaced silently.
2. repos.ecosyste.ms lookup: canonical name, fork flag and parent, archived flag, last sync time. Repair pass 2 (skeptic m1): a 404 there no longer leaves the path as it was. A successor search (PyPI project URLs, the packages.ecosyste.ms package record, WebSearch, README links, `git ls-remote` of each path) is recorded in SUCCESSOR_SEARCH.jsonl, and when another path serves the same HEAD and has a record, that path becomes canonical with its flags (PI-D-025). This moved TheClimateCorporation/properscoring to properscoring/properscoring (archived), JoelForamitti/agentpy to jofmi/agentpy and pandera-dev/pandera to unionai-oss/pandera; quantscious/finmlkit keeps its path on its packages.ecosyste.ms record.
3. `git clone --depth 1 --filter=blob:none --no-checkout`: clone HEAD must equal the pin (every reachable input did; 4 vanished). License files at the root (or under `LICENSES/`, REUSE layout) are read at the pin, hashed (sha256 of the file bytes since repair pass 2) and classified from their text; dependency files at the root are scanned for GPU, LLM, memory-service and server packages. Nothing was installed or executed.
4. Treeless clones (`--filter=tree:0`) of all 132 candidates give root commits: only sktime/sktime and aeon-toolkit/aeon share one (aeon is a declared hard fork), recorded and not shortlisted. The forks and mirrors met in search results were checked the same way (MIRROR_CHECKS.jsonl).
5. Paths that serve the same HEAD as a candidate (renames such as microsoft/LightGBM to lightgbm-org/LightGBM) are counted once under the path the package metadata names.

## P42 and README-only claims

A candidate needs a verified tree at its pin with source code; a shortlisted row also needs code paths whose symbols are defined at the pin (SHORTLIST.csv `code_evidence_verified`, path, blob id and line). README text, marketing pages and docs tables earn nothing. Real cases met in the search (EXCLUSIONS.md section E): TheSenseAI/SenseAI (README claims price prediction with very high accuracy; no Python, no tests, no license) and Cooktrenches/Scan-Scam-AI-v1 (accuracy figures in a docs table, example-only datasets, a shuffled split, pickled models, no license). MiroFish's README calls it a prediction engine; that claim is not credited, and it is listed only as a behavioral scenario generator (no probability output anywhere in its backend at the pin). The checker's negative tests (`probes/check_candidates_negative.py`) show that a README path as code evidence, a symbol that is not defined, and a candidate with no source tree are each refused.

## Limitations

- GitHub search, topics and repository REST endpoints were unavailable (HTTP 403 policy). Topic coverage came from the package keyword index, which only sees repositories that publish a package with keywords; repositories without packages were reachable only through WebSearch, documentation and paper links.
- The keyword index lists recent packages first, and its first two pages are dominated by new, small packages; established libraries were mostly found through documentation, WebSearch, PyPI cross-links and the seed list.
- ecosyste.ms metadata is a mirror (its `last_synced_at` is in each row); it still shows microsoft/autogen as not archived while the README at the pin says it is.
- WebSearch results have no body hash; the result URLs are copied verbatim with the batch window.
- Popularity was not recorded or used. Activity is the pinned commit date; INACTIVE_18M marks a last commit before 2025-04-24.
- Model-weight terms (TabPFN, TimesFM, Chronos, TabICL) are read from the repositories' own README notices; the weight license files live on Hugging Face and are for Phase 03 to read.
- The MiroFish maintainer FAQ (issue 726) was not reachable: GitHub issue pages and the issues API are behind the same 403 policy. Phase 03 should read it through another route.
- Independent discovery is lower than the raw credit count: W21 to W28 ran after the first 107 candidates were annotated (03:21:01Z), so they confirm choices already made, and several credits come from queries that name the target (for example W18 ABIDES, W19 TimesFM, W20 Graphiti, W26 netcal) or from the project's own page (D01 for scikit-learn, D03 for MiroFish).
