# Shared synthetic challenge: provenance and a known limitation

All five Phase 03 reviewers ran their smokes on one synthetic file written by the orchestrator: `challenge.csv` (3,000 rows, 444 KB, sha256 `18fda40cc7a2a6f5aa607a32f1a096976317f901f5b75d1ae23b4bcaddd5f23d`), generated by `make_challenge.py` (seed 20261024, sha256 `23cfab07a032c21dfe1e2ef12f7de817737bbde8bd332d5f2e2c1c4ee6cae535`). Both hashes are in `SHA256SUMS` (copied from `/home/claude/pi_research/challenge/`). The lead regenerated the file with `python3 -I make_challenge.py <dir>` and got the same sha256, so the CSV is reproducible; it is committed here because it is under 1 MB.

The data are synthetic. They test format and behaviour only and are never evidence of memecoin predictive value.

## The limitation (found by reviewer R2, reproduced by the lead)

The `split` column puts an "embargo" band of 14.6 h between the last validation decision and the first holdout decision, but every label runs 24 h (`label_matures_at = decision_time + 86400`), and there is no band at all between train and val. Reproduced by `overlap_effect.py` (output `overlap_effect.out.txt`, run with the MAPIE research venv: scikit-learn 1.9.1, pandas 3.1.0, numpy 2.5.4, inside `unshare -n`, exit 0):

| Count | Value |
|---|---:|
| val rows whose label matures after the first holdout decision | 45 |
| train rows whose label matures after the first val decision | 96 |
| train rows whose label matures after the first holdout decision | 0 |
| censored rows (label empty), all in the holdout | 107 |

## Which smoke metrics it could affect

On real data, an overlapping label window shares a price path with later rows and can inflate a score. In this generator it cannot: each row's label is drawn from that row's own features and an independent uniform draw (`make_challenge.py`, `z = ...` and `y = (rng.random(N) < p)`), there is no shared price path and no mint-level effect, so a label carries no information about any other row. The lead's check confirms it numerically: holdout Brier for a logistic model fitted on all 1,746 train rows is 0.030994 (equal to R1's scikit-learn smoke) and on the 1,650 purged rows 0.030893 (equal to R2's shared base model); sigmoid calibration on all 556 val rows versus the 511 purged rows changes holdout Brier by 0.000042. The largest difference is 0.000101, and the purged versions score slightly better, not worse.

That 0.0001 is one logistic draw, not a general bound (skeptic m3). The skeptic's placebo test (`../../../skeptic/p03/skeptic_embargo_test.py`; the lead's rerun in the MAPIE venv gave identical numbers, `placebo_lead_rerun.out.txt`) drops the same number of random non-overlapping train rows instead of the overlapping ones:

| Model | Purge changes holdout Brier by | Placebo median | Placebo 95th percentile | Placebo max | Purge percentile in the placebo |
|---|---:|---:|---:|---:|---:|
| logistic (200 placebo runs) | 0.000102 | 0.000068 | 0.000214 | 0.000432 | 69th |
| HistGradientBoosting (60 placebo runs) | 0.000858 | 0.000850 | 0.001826 | 0.002346 | 52nd |

So the honest statement is: on this generator label overlap cannot inflate a metric (each label depends only on its own row), and differences of up to about 0.002 Brier between purged and unpurged fits are sample-size noise, the same as dropping any 96 rows. The purge differences sit in the middle of the placebo spread for both models.

| Smoke family | Used the overlap? | Possible effect on its numbers |
|---|---|---|
| R1 (scikit-learn, LightGBM, interpret, TabPFN, statsmodels, feast) | fits on all train rows, scores the holdout; scikit-learn S4 calibrates on all val rows | train labels never reach the holdout (0 rows), so train-only holdout metrics are untouched; the val calibration in scikit-learn S4 includes the 45 rows; inside the placebo noise here |
| R2 (MAPIE, crepes, venn-abers, model-diagnostics, arch, mlfinpy, purgedcv) | purged both bands (fit 1,650, calibration 511) | none |
| R3 (lifelines, hazardous, river, sktime) | lifelines and hazardous fit on train and score the holdout; hazardous recalibrates on all val rows; river releases each label at its own maturity; sktime counts unmatured labels directly | only the hazardous recalibration includes the 45 rows; inside the placebo noise here |
| R3 (tsfresh, ruptures, stumpy) | own seeded price paths, not the challenge | none |
| R4 (evidently, nannyml, frouros, mlflow, skore, pandera) | drift tests use features only; models fitted on train; NannyML's CBPE reference is all val rows; skore's CV uses train plus val | CBPE reference and skore CV include overlapping rows; inside the placebo noise here |
| R5 (MiroFish, OASIS, mesa, black-it) | no fitted labels (mesa scores the holdout with a simulator) | none |

## Rule the lead applied

No rubric point in `research/SCORE_ITEMS.csv` rests on a holdout metric difference that this overlap could inflate. Temporal points rest on mechanisms checked at row level (independent overlap counts, truncation tests, refused or nulled rows), never on "the score went down after purging". Holdout scores on this file are format checks; they earn no skill points. A consequence the lead records as a limitation: because labels are independent, this challenge cannot show that a library which ignores label overlap would leak on real data; that is why purge and embargo were credited only where an independent overlap checker counted zero overlapping training rows (purgedcv), and not because a metric looked honest.
