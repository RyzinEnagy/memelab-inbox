## P31 (AGPL code copied): caught

- Strong copyleft at the pin: MiroFish and black-it (MI-1, BI-2). Both have L1 = 0, ISOLATED_RESEARCH decisions and are never INSTALL or ADAPTER; `verify/check_scorecard.py` refuses an L1 point or an in-process decision for them (negative tests `m_agpl_l1`, `m_agpl_install`).
- Copyleft hiding under a permissive label: mlfinpy (MIT) carries BSD-3 mlfinlab code without the required notice (MF-2), so its rights are unverified and it is REJECT. GPL igraph inside Apache-2.0 OASIS keeps OASIS in a separate process.
- One rule for unknown or violated rights (PI-D-029): content whose rights are unknown or violated makes a repository REJECT outright when the recommended route has to install, import or run it, and REJECT for that route only when the route can leave it out. mlfinpy's unnoticed BSD-3 code is the cross-validation module its role runs, so it is REJECT outright; OASIS's real Twitter propagation pickles sit in `data/`, are not loaded by the package and are never used, so they carry a route-level REJECT and OASIS stays ISOLATED_RESEARCH; hazardous's SEER and METABRIC files are only in the PyPI 0.2.0 artifacts, so that route is REJECT and the pinned source is not.
- Repository scan: no AGPL source in the lab (`grep` for the AGPL title and the black-it copyright line finds only the license review and a Phase 02 classifier string).

## P32 (poisoned or unsafe install): caught

- hazardous 0.2.0: release contents differ from every source commit and include 214 MB of registry data (HZ-1): REJECT for that route.
- TabPFN: weights fetched from a moving `main` revision and `.ckpt` unpickled through `torch.load` legacy mode: pin by sha256 and fetch once.
- river: building the pin silently updated the host's Rust toolchain; install wheels only.
- black-it and every pickle-based format: restore only files the lab wrote.
- No install-time network or destructive script was found in any reviewed `setup.py`, build hook or sdist (MiroFish's two sdists, langdetect and docopt, are plain `setup()`).

## Excluded from the commit by the hygiene scan

`SMOKES/lorentzenchr__model-diagnostics/reliability_base_vs_leaky.png` (an 800 x 320 PNG plot, sha256 `dfd0c4f9...`) was removed as a binary; the same numbers are in `raw_smoke_model_diagnostics.txt`. No secrets, tokens, weights, tokenizer files, wheels, pickles or files over 1 MB were found in SMOKES or REVIEWS; the simulator smoke logs hold request sizes and hashes only, no third-party social content; the fictional profile strings in the MiroFish smoke input were replaced by hashes in the repair pass because the lab content guard bars a stored `bio` key.
