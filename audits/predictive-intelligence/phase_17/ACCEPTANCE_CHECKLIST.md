## Frozen rules of integration-1 (fixed here, before any code)

1. Hook. `memelab/cli.py` gets one helper per command. `cmd_scout`: after the existing report text and its path exist and before the file is written, `pred = _predictive_section(results, s2, t, path)`; when it is not None, `md += "\n" + pred` (appended after the unchanged body, the social section included). `cmd_analyze`: after the existing print line, one extra line when the helper returns one. Each helper imports `memelab.predictive.integration` lazily inside its body; an ImportError returns None. When the flag is off the integration returns None before it opens any file other than the config, so nothing is written and the output is byte-identical (P40).
2. Trigger and unit. A trigger is one pipeline result (the scout's or analyze's `analyze_token` output). Its decision snapshot is the thesis row the pipeline just persisted, read back read-only from the lab database by `(mint, created_at = bundle observed_at)`, newest id; `snapshot_hash` is `decisions.row_sha256` of that row (the row without `id`, PI-D-022: the value a later state export of the same row carries). Decision time basis CAPTURE_TIME: the wall clock when the request is created, passed by the caller (PI-D-015); it must be at or after the row's `created_at`, else ERROR. A result without a persisted row is NO_DECISION_SNAPSHOT (visible, not attempted); a mint that is not an exact address of its chain is NOT_EXACT_IDENTITY (visible, not attempted). Identity is `(chain, mint)` byte for byte (P01).
3. Exactly once. Each trigger gets exactly one request record with one event: DISCOVERY (first attempt for the chain and mint), MATERIAL_CHANGE, UNCHANGED (cache hit: covered by the last attempt, no new document), DUPLICATE (this exact snapshot was already attempted: no new document), SUPERSEDED_IN_PASS, DEFERRED_QUEUE_FULL, DEFERRED_LATENCY_BUDGET, NO_DECISION_SNAPSHOT, NOT_EXACT_IDENTITY or ERROR. An attempted event (DISCOVERY or MATERIAL_CHANGE) gets exactly one contract document and one abstention-1 record per primary target (three), with `forecast_id = contract.forecast_id(chain, mint, snapshot_hash, target, target_version, horizon, model_sha)` (model sha `none` when not selected) (P35). Non-primary registry targets are listed in the request as not attempted with TARGET_NOT_FEASIBLE (`registry.target_plan`).
4. Material change gate, against the last attempted request of the same chain and mint. MATERIAL when any of: pool, status, the set of fatal flags, the exact-address catalyst fingerprint (rule 9), the served model sha or pin event of any primary target differs; the integer score moved by 5 or more; price moved by 10% or more (relative); liquidity by 20% or more; 24 h volume by 50% or more; a price, liquidity or volume became known or unknown; the last attempt is 3,600 s or more before this capture. Otherwise UNCHANGED, with the covering forecast ids and the measured changes. DUPLICATE is checked before the gate.
5. Bounded work per pass (P35, P48). At most 64 attempted events per pass; at most one per (chain, mint) per pass (the newest snapshot; the others SUPERSEDED_IN_PASS); events past the cap DEFERRED_QUEUE_FULL; a pass time budget of 30 s (injected monotonic clock), events reached after it DEFERRED_LATENCY_BUDGET. Work is linear: three targets per attempted event, no pairwise loop over mints or events. No retry and no background job: deferred events are visible and wait for the next scout pass (no scheduler is approved, PI-D-005).
6. Network and cost (P48). integration-1 itself opens no socket. A reference-price read happens only when a champion is served for a target and the caller supplied a reader; it goes through `runtime.CallGuard` (6 a minute, at most 64 calls a pass, a breaker after 5 consecutive failures, cost cap 0 so any priced call is refused before it is made) and at most one read per request (ACCEPTANCE `inference_reads_per_request` 1, timeout 10 s). The lab's CLI passes no reader, so the real path makes no call. Otherwise eligibility is NOT_ASSESSED, which the abstention layer reports as SOURCE_STALE with that detail.
7. Serving. Each primary target is resolved only through `registry.serve` on the committed Phase 16 registry (`audits/predictive-intelligence/phase_16/registry/`, log chain checked by `read_log`, entries by `read_entries`), `root` = the repository, as of the decision time, with runtime facts for family 07 (feature set sha, feature version 2, `baselines-phase07`, registry fingerprint, `labels-1`). integration-1 has a feature builder for family 07 only: a champion of families 08 to 11 is refused as MODEL_INCOMPATIBLE_RETRAIN_REQUIRED (fail closed). A real champion gets `inference=None` (INFERENCE_NOT_CHECKED, abstain): integration-1 has no access to the Phase 12 probe inputs; only a fixture champion (`allow_fixture`, fixture runs only, never from the CLI) gets recomputed rows over the committed synthetic probe set. Then `abstention.forecast_result` with serve's `forecast_inputs` (card, level and calibration card only from the registry), the flag read from the config by the layer, and `abstention.validate_publication` with the persisted record (rule 11). A registry that cannot be read or verified gives REGISTRY_UNAVAILABLE: every target abstains MODEL_NOT_SELECTED with the detail, visible (P47).
8. As-of features. Computed only when a champion is served or in research mode: an in-memory capture store with the single decision row and its token row as one capture version at the capture time, then `features.features_as_of(..., mode="capture")`, feature version 2, and `baselines.model_inputs`. Only the family-07 card columns are used; history, universe and candle groups are missing with their reasons (scope CAPTURE_SINGLE_ROW, recorded). Inputs older than 7,200 s at the capture (bundle `observed_at`) are INPUT_STALE: eligibility INPUT_STALE, so every target abstains SOURCE_STALE with that detail, visible (P47).
9. Catalyst changes. Exact-address links only: `catalyst_token_links` with the same chain and mint byte for byte, link type OFFICIAL or NAMED_IN_SOURCE and strength STRONG (PI-D-007), linked and discovered at or before the capture; one event counts once by `event_key` however many sources carry it (P15). The fingerprint is part of the material key (rule 4). A catalyst pass (`catalyst_pass`) turns a new exact-address link for a mint that already has an attempted request into REFRESH_REQUESTED (visible, at most one per mint per 3,600 s, deduplicated by event key); a ticker or name link is IGNORED UNVERIFIED_CATALYST; a mint without an attempted request is IGNORED NO_DECISION_SNAPSHOT (the scout must analyse it first); absent catalyst tables are CATALYST_SOURCE_NOT_AVAILABLE. A refresh never changes a document, a verdict, a score or a status.
10. Decision support beside every attempted event: `onchain.decision_support` with the lab's fatal flags, collector quotes through `depth_adapter` when a collector file is configured (else COLLECTOR_NOT_AVAILABLE and no quotes), the decision time, the decision pool, `max_loss` 0.05 and `max_age_s` 3,600; the backtest adapter's fatal or structurally untradeable state is an extra veto; `position_usd` is always None; a forecast never clears a veto (fatal flaw override always wins).
11. Documents never travel alone (Phase 13 m4). A document is persisted, rendered or counted only with its abstention record; `integration.check_document` refuses a document without its record, a record of another forecast, or reasons that differ. The renderer takes reasons and plain explanations from the record.
12. Published point recomputed (Phase 13 m3, PI-D-068). The request record keeps the champion's raw number and the calibration card sha for every target; `integration.verify_point` recomputes the calibrated point and interval from them (`abstention.evaluate`) and refuses a FORECAST whose probability or interval differs (tolerance 1e-12). This runs before anything is persisted or shown.
13. Backtesting. On this branch `memelab.backtest` is not importable, so every document carries BACKTEST_NOT_AVAILABLE (`contract.backtest_status`). `bt_adapter` (read-only, standard library only, never imports `memelab.backtest`) reads an assessment record attached to a scout result (`backtest_assessment`, the shape `assess.attach` writes at `69bc5c3`) or the `bt_assessments` table opened `mode=ro`; it refuses another chain or mint, an assessment made after the decision, an unknown state and a schema mismatch; its output goes only into the request record, never into the document (the contract refuses an assessment reference unless VERIFIED). TEST_ONLY until the module is merged and a phase verifies it.
14. Persistence. State directory `data/private/predictive/` (gitignored) unless the config names `predictive.state_dir`: `REQUESTS.jsonl`, `DOCUMENTS.jsonl`, `RECORDS.jsonl`, `REFERENCE_RECORDS.jsonl` (research mode: B0 and B2 raw numbers through `registry.reference_record`, never documents) and `PASSES.jsonl`. Every line carries a record id equal to its content hash; every append goes through `abstention.append` with the file sha the previous pass recorded, so a changed, dropped or reordered line refuses the pass (STATE_TAMPERED, visible, nothing written). Earlier records are never rewritten (P39).
15. The section. Plain language, research only, no trading word (`abstention.describe`), no number when abstaining. It names: the flag, BACKTEST_NOT_AVAILABLE, the registry mode and pin reasons per target, the Phase 13 calibration status per target, per token the exact `chain:mint`, the snapshot sha, the event, the fatal-flag veto, the size basis, every target's status with the record's reasons and record id, the token report path, and the ops metrics (rule 16). It states that the score, fatal flags, status and lists above are unchanged.
16. Ops metrics (per pass and over the state): events, attempted, completed (FORECAST documents), abstained, unchanged (cache hits), duplicates, superseded, deferred, errors, reader calls, latency p50 and max (ms), model ids in use, reason counts. CLI: `python -m memelab.predictive.integration status|catalyst-pass|check --state-dir DIR` (no change to `memelab/cli.py` `main`).
17. Isolation. integration.py imports only the standard library and `contract`, `registry`, `abstention`, `calibration`, `baselines`, `features`, `labels`, `runtime`, `store`, `decisions`, `onchain`, `depth_adapter` and `bt_adapter`; no network module; never `memelab.backtest`. Only `memelab/cli.py` imports it, lazily. The isolation tests of Phases 01, 09, 13 and 16 (`test_no_existing_module_imports_the_predictive_package`, `test_no_other_module_imports_the_phase_09_code`, `test_the_phase_13_modules_use_numpy_and_the_standard_library_only_and_nothing_imports_them`, `test_no_other_module_imports_the_registry`) are amended to allow exactly these two seams and nothing else; each amendment keeps a negative case showing that any other importer still fails. The isolation tests of Phases 10, 11, 12, 14 and 15 are not changed (integration-1 does not import or name those modules).

## Counterexample CX-17 (pre-registered)

Wrong but plausible: a cache keyed on the decision content alone (mint, price, liquidity, status, flags) reuses the last result for an unchanged snapshot. If a champion is pinned and then rolled back (or a new pin appears), an unchanged snapshot keeps showing the withdrawn FORECAST, or keeps abstaining when a newly pinned champion could answer. Caught by rule 4: the served model sha and the pin event id of every primary target are in the material key, so a pin change is MATERIAL. Test: a fixture champion pinned, an attempt, a rollback, the same content again: MATERIAL_CHANGE and the new documents abstain; with the pin removed from the key the test fails.
