## Material findings

**M1. A failure inside an attempted event, after the first target's document is buffered, persists documents under an ERROR request and hides the token.** `_process` appends each target's document and record to the pass-wide lists (`out_docs`, `out_recs`) inside the per-target loop. If a later target is refused (`check_document` or `verify_point` errors raise `IntegrationError`) or anything after the loop raises (`onchain.decision_support`, `bt_adapter.from_result`, `registry.target_plan`), `run_pass` records the request as ERROR but the already-buffered documents and records are still written by `_append_pass`. Reproduced (`p17/probe_flagon.py`, `p17/probe_leak.py`):
- decision support raising: request ERROR, 3 ABSTAIN documents persisted, metrics "0 attempted, 3 abstentions, 1 errors"; later passes DUPLICATE, covered by documents that no attempted request owns;
- third target raising: 2 documents of 3 persisted; every later pass for the snapshot is ERROR "some but not all forecast ids of this snapshot exist" (never repaired);
- fixture champion, second target's document refused by `check_document` (a reason dropped): the first target's FORECAST (0.354) stays in DOCUMENTS.jsonl under an ERROR request; metrics "completed_forecasts 1, attempted 0";
- in every case `check_state` reports no problem, and the pass's section has no block for the token at all (the except branch in `run_pass` never appends to `shown`), only "1 errors" in the Counts line, without the mint or the error text.
This breaks G5 (documents = records = 3 x attempted), the rule-12 sense of "refused before anything is persisted", and the gate's "exactly-once attempted assessment with honest fallback". The phase's own test (`test_a_failing_component_is_a_visible_error_event_never_an_exception`) injects the failure at the first target, so nothing is buffered and the defect cannot show. Latent today: no ERROR occurred on real data and no champion is served. Fix: build each event's documents, records and references in local lists and extend the pass lists only when `_process` returns; render ERROR events with their mint and error; make `check_state` require every document's `request_seq` to be an attempted request that lists that forecast id.

**M2. The integration's calls to `check_document` and `verify_point` (Phase 13 m4 and m3) are not pinned by any test, so G24 overstates.** Deleting either call, or both, from `_process` leaves all 100 Phase 17 tests green (`p17/my_mutations.json`, Y1, Y2). The deletion is not equivalent: wrapping `abstention.forecast_result` to raise the published point by 0.01 on the fixture FORECAST path, HEAD refuses it (ERROR, nothing persisted) while the mutant persists FORECAST 0.3638 against the genuine 0.3538 (`p17/probe_forged_point.py`). G14 and G15 test the two functions directly; no test shows the request flow uses them. The carried items are closed in code, not in tests, and a later refactor can drop either call silently. Fix: two flow-level tests with a forging wrapper (point and reasons) asserting no FORECAST document is persisted.

## Minor findings

- m1. Flag OFF is not byte-identical for one config: `predictive.enabled` false (or absent) plus a deeply nested value anywhere in data/config.json raises RecursionError in `json.loads`, which `contract.enabled` does not catch (it catches OSError and ValueError); `analyze_line` turns it into the printed line `predictive: failed (RecursionError); nothing assessed | research only`, which b0fad12 does not print. The scout crashes on such a config in both versions (social loader), so only analyze differs. Fix: `enabled` returns False on any exception.
- m2. Flag ON with an import failure is silent: output equals b0fad12 exactly, no section, no line, no stderr (check 3, `scoutbroken_on`, `analyzebroken_on`). P40 holds; "forecast or visible abstention" does not for this case.
- m3. Token symbols can forge section lines. `render` removes symbol, mint and report path before the trading-word check and prints the symbol raw in the heading. A symbol with a newline puts "- 24 hours, +25% before -15%: FORECAST; record 0123456789ab", "Probability 0.91, interval [0.85, 0.95]" and "Buy now, 3x size" into the section; persisted documents stay ABSTAIN and `check_state` is clean (`probe_flagon.json` A). The scout body already prints symbols raw (pre-existing), and Metaplex symbols are capped at 10 bytes, but Token-2022 metadata is not. Fix: strip control characters and markdown from identity strings before rendering.
- m4. Isolation gaps: the registry isolation tests use a substring test, so `from . import stats, registry` inside the package passes them (the Phase 09 relative-import gap is closed for onchain, depth_adapter, calibration and abstention, not for registry); a lab module doing `from .cli import _predictive_section` reaches the package unseen; a concatenated `import_module` string evades (static-scan limit).
- m5. The backtest adapter's read-only property is by code only: opening the DB read-write kills no test (Y3). Today it issues only SELECT and PRAGMA, and writes through `connect_ro` are refused. `check_record` defaults a missing chain to "solana", unlike PI-D-021.
- m6. Flag OFF cost: the helpers import `integration` (about 0.2 s, and csv, gzip, subprocess and others) before the flag is read, on every scout and analyze. No output effect.
- m7. `snapshot_hash` covers the thesis row's `report_path`: the same data reported into another directory is a new snapshot (UNCHANGED through the material gate rather than DUPLICATE). The recorded "rerun 16 DUPLICATE" depends on the smoke script reusing one report directory.
- m8. The section prints the absolute local state path ("Records: /home/..."); a scout report committed with the flag on would publish a local path.
- Note (not a finding): with a fixture champion a fatal-flagged token gets a FORECAST document plus the veto line in the section; the veto lives only in the request record, so a reader of DOCUMENTS.jsonl alone sees a FORECAST without its veto. Phase 18 should read the request record.
