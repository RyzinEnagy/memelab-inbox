## Severity classes (fixed here)

- CRITICAL: a published number or a training row that uses information not available at its decision (feature, label, model, report leak), a forecast number published where the contract says abstain, a fake executable quote or a size from a probability, copyleft code in the repository, a trade, signing or private-key path, an unbounded or unapproved spend path, a change of the existing lab's flag-off output or of its 100-point score or fatal flags, a write under tracked `inbox/`, `state/` or `data/`. Any CRITICAL stops the release (NO_GO_DECISION_TREE.md): Phase 20 is FAILED and Phase 21 must record NOT READY.
- MATERIAL: a defect that can produce a wrong record, a wrong verdict, a wrong identity or a misleading claim under a plausible input, even when it is latent today (no champion, flag OFF); or a gate item whose evidence is missing or wrong. A MATERIAL finding is repaired (change control, test failing on the audited code, touched paths rerun) or explicitly accepted by the orchestrator or Elving before Phase 20 can be PASS.
- MINOR: a records inconsistency, a docstring or claim that overstates, a defense-in-depth gap with no reachable failure on any path the lab runs, test hygiene. Listed with a recommendation; does not block.
- Each finding gets an id F20-NN, the component, the reproduction (command, input, exit code, observed against expected), the severity before any repair, and the outcome (OPEN, REPAIRED with the commit and the test, ACCEPTED with who accepted it).

## Scenario method for G2 (fixed here)

- One function per scenario in `probes/scenarios.py`; `python -B probes/scenarios.py Pxx` runs it in its own process with an audit hook that refuses sockets, temp files only, a fixed clock, and prints a JSON object (scenario, trap, assertions with each `expect` and `observed`, result). Exit 0 when every assertion holds, 1 when one fails, 2 when the check itself cannot run. `probes/run_matrix.py` runs all 48 commands, keeps each raw output in `qa/raw/`, runs the mapped existing tests once in one pytest call with a junit file, and writes `qa/SCENARIO_MATRIX.csv` (id, trap, required behaviour, component, check command, exit code, assertions passed of total, result, mapped tests and their outcomes, unpatched severity if failing, notes).
- Results: PASS (every own assertion holds and the mapped tests pass), PASS_EXPECTED_ERROR (the required behaviour is a refusal or a named state and the assertions prove it), TEST_ONLY (proved on fixtures because the live path does not exist, for example MiroFish, a FORECAST, a VERIFIED catalyst), N_A (only with code or data proof and an explicit risk acceptance in the findings file), FAIL (a finding).
- The checks use the integrated entry points where one exists (`integration.run_pass` with a fixture champion, `reports.build`, `monitoring.append`, `registry.serve`, `abstention.forecast_result`) and the component function otherwise. A check may reuse the test files' fixture builders; its planted input and its assertions are its own.
